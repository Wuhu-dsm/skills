# Interviewer Perspective

Use this reference when the user asks for feedback from an interviewer or hiring evaluator viewpoint.

## What Interviewers Are Looking For

Vibe coding interviews usually evaluate more than code completion. Strong candidates show:

- Clear requirement clarification before implementation.
- Ability to use AI without surrendering judgment.
- Good product instincts and user workflow awareness.
- Fast but careful codebase reading.
- Small, coherent implementation steps.
- Evidence-based debugging.
- Practical testing and validation.
- Concise explanation of tradeoffs.

## Hiring Signal Levels

### Strong Signal

The candidate clarifies scope, builds a working solution, validates important behavior, uses AI deliberately, and explains decisions clearly. Imperfect code can still be strong if the candidate demonstrates control and judgment.

### Mixed Signal

The candidate makes progress but has visible gaps: weak validation, unclear reasoning, too much reliance on AI output, overbuilt scope, or incomplete edge cases. This often means they need more structured practice rather than a full reset.

### Weak Signal

The candidate cannot clarify the task, cannot explain the implementation, repeatedly accepts broken AI output, or does not verify whether the result works.

## Feedback Principles

- Ground every criticism in observed behavior.
- Separate correctness issues from interview communication issues.
- Mention whether the issue would affect hiring signal.
- Give one to three concrete next practice targets.
- Avoid vague comments like "be more confident" unless paired with observable behavior.

## Useful Interviewer Questions

- What user workflow are you optimizing for first?
- What assumptions are you making?
- What would you cut if you had only 15 minutes left?
- How would you verify this works?
- What did the AI help with, and what did you personally validate?
- What part of this implementation feels most fragile?
- If this were a real codebase, what follow-up would you leave for later?
